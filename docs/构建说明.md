# 构建与验证

使用 PowerShell，在项目根目录执行：

```powershell
.\scripts\prepare.ps1
.\scripts\build.ps1 -Publish
.\启动塞西莉亚的图书馆.ps1
```

`prepare.ps1` 下载并核对官方 .NET SDK，准备固定版本的开发依赖，以及 Word 和表格两个小组件。开发 SDK 位于 `.tools/dotnet`；NuGet 包位于 `.packages`。Node.js 仅用于开发。

需要完整办公兼容组件时执行：

```powershell
.\scripts\prepare-components.ps1 -Components office
```

成品位于 `dist/LightReader`。根目录启动入口使用 `.local-data` 保存本项目预览版的设置与缓存，并复用项目中已准备的组件。直接运行成品 EXE 时使用用户的本地应用数据目录，缺少组件后按需安装。

测试样本可以用 `scripts/make-fixtures.py` 和 `scripts/make-sheet-fixtures.cjs` 生成；Office 旧格式样本由 LibreOffice 文档记录的导出过滤器生成。ODT 使用 `scripts/make-odt-fixture.ps1` 从自生成的 Word 样本导出。XLA / XLAM 使用 SheetJS 的加载项输出类型生成，包含三张隐藏工作表。样本来源、哈希和大小在 `data/fixture-manifest.json`。

核心检查：

```powershell
.\.tools\dotnet\dotnet.exe run --project tests/LightReader.Checks -c Release -- $PWD
```

实际窗口集成检查使用应用的 `--verify 项目目录 --data-dir 隔离测试目录` 参数，只打开测试样本，输出 `reports/gui-checks.json` 与预览截图。报告会逐份刷新；最后一项为 `flow:no unhandled UI errors` 才表示整轮完成，独立核对和报告生成脚本会检查这个标记。启动及内存测量脚本为 `scripts/benchmark.ps1`；独立 PDF 和保存结果检查脚本为 `scripts/check-output.py`。

0.1.1 的预览逻辑检查：

```powershell
node .\scripts\check-preview-behavior.cjs --output tmp\preview-behavior.json
```

脚本直接检查当前 TypeScript 源码，包含表格按需格式化、跨工作表查找、位置恢复，以及文件切换时旧结果的取消。它使用 Node 的模拟运行环境，不能代替浏览器排版、实际鼠标和打印验收。`--output` 只接受项目 `tmp` 内的路径；省略该参数时结果仅输出到终端。

表格解析器诊断可以运行 `node scripts/compare-sheet-formatting.cjs`，输出在 `tmp/sheet-formatting-experiment.json`。它需要下述大表格合成样本，并逐份比较格式显示，再用独立 Node 进程测三轮解析；软件整体占用以生命周期报告为准。

阅读生命周期测量（打开、返回首页、反复开关文件）：

```powershell
python .\scripts\make-memory-fixtures.py
.\scripts\measure-reading-lifecycle.ps1 -Label after -Iterations 10 -Report tmp\memory-lifecycle-after.json
.\scripts\measure-reading-lifecycle.ps1 -Label pdf -Iterations 10 -PdfOnly -Report tmp\memory-lifecycle-pdf.json
```

样本生成脚本需要 Python 的 `python-docx` 和 `openpyxl`，在 `tmp/memory-fixtures` 生成分成 30 段、段间插入分页符的 DOCX，以及含 50,000 条数据行的 XLSX。完整生命周期检查需要项目已准备 Word 和表格组件；`-PdfOnly` 单独检查原生 PDF 的反复打开、返回首页和文件流释放。PDF 连续翻页与缩放由 `--verify` 的阅读稳定性检查覆盖。

测量脚本默认使用 `dist/LightReader/LightReader.exe`；`-Application` 可指定项目内另一份程序。`-Label` 设置测试标签，`-Iterations` 设置反复开关次数，`-Report` 设置报告路径。未指定 `-Report` 时写入 `reports/memory-lifecycle-标签.json`。比较改动前后时使用相同样本、次数和机器条件，并保留报告里的程序哈希。`-AllowFailedChecks` 仅用于采集有意重现旧缺陷的基线；默认遇到失败检查会保留报告并报错。每轮使用 `tmp` 内的独立设置目录，包含组件联接；统计实际进程及此前观察到的子进程，不强制整理内存。记录的是各检查点的快照，长期压力和完整峰值仍须另测。

开发临时内容放在 `tmp`。测试结束后先退出测试实例、移除测试目录中的组件联接，再清理本次生成的临时目录。上述生命周期脚本会结束其测试进程，但不会自动删除样本和测试目录。需要留存的最终证据确认后放入 `reports`。

0.1.2 的六种 WPS 原生格式使用独立的公开样本清单，不混入自生成的 Office 样本。先运行 `scripts/prepare-native-wps-fixtures.ps1`，再按 [WPS 原生格式验证](WPS原生格式验证.md)运行结构、实际显示和独立内容检查。外部原件及页面图片保留在忽略目录，本仓库只保存来源、指纹和检查报告。

`scripts/make-report.py --formats-only` 根据完整窗口报告与原生格式的四类证据更新格式目标和格式清单。空白文件检查不会增加支持数量，原生样本缺少画面检查时也不会计入。

0.1.3 增加大表格搜索与极端 PDF 页面的检查。先运行 `python scripts/make-memory-fixtures.py`；除原有样本外，还生成含 600,000 条匹配的 XLSX 和 200 × 14,400 点的长页面 PDF。Python 需要 `python-docx`、`openpyxl` 与 `pypdf`。仅补长页面样本可以加 `--pdf-only`，不会重写用于内存对比的表格和 Word 样本。

```powershell
.\scripts\measure-reading-lifecycle.ps1 -Label search -SearchOnly -Iterations 3 -Report tmp\memory-search.json
python scripts\check-pdf-pixels.py --baseline e6414ac --output reports\pdf-pixel-013.json
```

`-SearchOnly` 核对每轮 600,000 条匹配、清空搜索及回首页后的视图释放，内存仍以完整进程树统计。普通阅读与 `-PdfOnly` 单独顺序运行，避免测试窗口相互影响。普通 PDF 的前后画面必须保持一致；极长页的图片总量限制为 16,777,216 像素，单边不超过 16,384 像素，受限时清晰度随整页缩小。

Windows“打开方式”的原生候选检查：

```powershell
.\scripts\check-windows-open-with.ps1
```

脚本只读查询当前用户的候选应用，分别检查全部候选和推荐候选中的名称、程序路径与推荐标记。结果写入 `reports/windows-open-with-checks.json`；该结果不替代实际右键菜单和应用选择窗口的显示验收。
