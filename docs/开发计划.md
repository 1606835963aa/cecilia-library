# 轻量化文档查看器开发计划

制定日期：2026-10-12

开发一个 Windows 本地文档查看器，覆盖 WPS 宣传的 47 种格式，以准确显示、方便阅读和较低资源占用为核心，提供少量基础编辑。采用小巧主程序加按需安装的格式组件；组件装好后可以离线使用。

已开始执行，形成 0.1.0 可运行预览版；当前证据和未完成项见 [开发进度](开发进度.md)。公开清单有 46 个后缀，用户已确认补入 ODT，形成 47 项目标。`.ts` 的含义继续核实。格式目标以 [格式支持清单](格式支持清单.md) 和 [目标数据](../data/format-targets.json) 为准。

## 一 已确定的开发原则

- 主程序采用 C#、.NET 10 LTS、WPF 和 WebView2；预览页面使用 TypeScript、HTML 和 CSS。
- 不同格式由独立组件处理，主程序提供统一的打开和阅读体验。
- 文档在本机处理。查看和基础编辑不依赖账号、云端转换或上传文件。
- 先验证格式引擎，再完善界面，随后补齐格式覆盖和基础编辑。
- 基础编辑按具体操作验收，47 种格式覆盖主要指查看能力。
- 默认阅读，主动进入编辑；保存前核对原文件是否被其他程序修改。
- 程序界面保留正常字号的功能名称和必要状态，不添加密集说明小字。

安装全部组件后的体积可能较大。按需安装减少的是首次安装和未使用组件的占用，性能记录必须包含实际安装的全部依赖、缓存及后台进程。

## 二 软件结构

| 模块 | 职责 | 技术选择 |
|---|---|---|
| 主窗口 | 打开、拖入、多文件切换、快捷键、阅读工具 | WPF |
| 文件识别 | 结合后缀和文件内容判断格式，选择组件 | C# |
| 阅读容器 | 显示预览结果，处理缩放和搜索交互 | WebView2 或原生控件 |
| 文字预览 | 快速显示 DOCX 类文件 | docx-preview 候选 |
| 表格视图 | 切换工作表、查看单元格和已有计算结果 | SheetJS 社区版候选 |
| 办公兼容 | 旧版 Office、WPS 系列、幻灯片及复杂排版 | LibreOffice 独立进程候选 |
| 组件管理 | 下载、校验、安装、更新、回退和移除可选组件 | C# |
| 基础编辑 | 修改指定内容，并完成可靠的另存为 | 按具体格式验证后确定 |
| 设置与缓存 | 最近文件、阅读位置、预览缓存及清理 | 本地 JSON 与文件 |

格式组件统一返回查看结果、处理进度、错误原因和支持的操作。主程序能够取消处理；某个组件出错时，窗口仍能关闭当前文件或打开其他文件。

兼容组件初期按一个办公引擎管理。是否可以进一步拆小，由实际构建和体积验证决定。界面不按每个后缀各安装一套引擎。

## 三 阶段 0 格式定义和测试样本

工作内容：

1. 核对 46 个已列后缀，以及用户确认的补充项 ODT。
2. 明确 `.ts` 在 WPS 清单里的含义；`.xla`、`.xlam` 已定义为加载项内部静态表格数据查看。
3. 为普通文档、模板、含宏变体及不同年代版本分别登记样本。
4. 用自行生成或公开可使用的文件搭建样本库。需要用户文件时，仅使用用户明确选定的文件，日志不记录正文和密码。
5. 为每个样本保存来源、文件哈希、内容核对点及参考显示结果。兼容样本必须有符合其格式的内容，不能用改后缀的方式凑数。

重点样本包括中文、图片、复杂表格、页眉页脚、分页、图表、公式结果、日期、长编号、前导零、多页 TIFF、扫描 PDF，以及需要配套长文本文件的 DBF。

交付物：样本目录和样本清单；特殊格式定义记录；更新后的格式目标数据。

验收：每个已定义格式都有明确的查看对象和核对方法。缺少定义的项目继续保留待核实状态，不妨碍其他格式推进。

## 四 阶段 1 验证显示引擎和实际占用

工作内容：

1. 准备 .NET 10 开发工具，建立最小 Windows 程序。
2. 验证 PDF、文本、图片及多页 TIFF 的打开效果。
3. 验证 DOCX 快速预览的文字、表格、图片、分页和字体。
4. 验证 XLSX、XLS、CSV 的单元格值、工作表切换、合并区域、日期和数字格式。
5. 在独立后台进程中验证 DOC、PPT、PPTX 及 WPS 系列的兼容读取或转换。
6. 比较快速预览与办公引擎的实际效果，记录首次启动、打开时间、峰值内存、组件大小和转换后缓存。
7. 核对各依赖的使用和分发许可。LibreOffice 作为第一兼容候选；若关键格式无法达标，再评估 ONLYOFFICE 或其他文档组件。

交付物：可运行的最小验证程序、引擎对比结果、依赖及版本清单、性能基线记录。

验收：PDF、DOCX、XLSX 在本软件窗口内显示，并完成内容核对；旧格式、幻灯片及 WPS 系列的可行性已有实测结果。只有查看和保存行为已验证的组件才能进入对应发布范围。

如果候选组件无法满足某种复杂排版，先调整该格式的实现方案。某项引擎失败不能被记录为格式已支持，也不应使其他独立模块全部停工。

## 五 阶段 2 完成统一阅读软件

工作内容：

1. 实现文件选择、拖入、命令行传入文件及多文件标签。
2. 接入已经验证的格式组件，实现后台处理、进度和取消。
3. 提供缩放、适合宽度、页码跳转、搜索、复制和打印入口；具体操作按文件类型启用。
4. 表格提供工作表切换和单元格数据视图；复杂页面布局提供分页预览。
5. 保存最近文件和阅读位置，提供清除记录及缓存的操作。
6. 处理不存在的文件、损坏文件、缺失组件、密码输入以及后台引擎退出。

交付物：可以日常打开和阅读已验证格式的本地预览版。

验收：鼠标和快捷键完成主要阅读操作；快速切换文件不会显示上一份文件的结果；取消和关闭文件不会留下持续工作的兼容进程；中文路径正常；界面操作保持响应。

## 六 阶段 3 完成按需组件安装

工作内容：

1. 建立组件目录，登记组件版本、可处理的格式、实际下载量和安装占用。
2. 首次需要未安装组件时，提供名称、大小和“安装组件”操作；安装完成后自动继续打开文件。
3. 实现下载进度、取消、断点或重试、内容校验及完整安装后的切换。
4. 更新失败时保留原有可用版本；取消下载时清理本次临时内容。
5. 允许移除可选组件及预览缓存，保留用户文件和软件设置。
6. 检测 .NET 桌面运行时和 WebView2 是否存在，分别统计已有与缺失依赖的安装情况。

交付物：组件安装与管理页面、组件清单、可复现的组件打包脚本。

验收：缺失、已安装、离线、中途取消和更新失败等情况都完成测试；安装后的组件能断网打开样本；下载或安装失败不会损坏已有组件。

## 七 阶段 4 补齐格式覆盖

按下面六组推进，完成一组就更新证据和实际支持数量。分组只决定工作顺序，最终目标保持完整。

| 组别 | 后缀 | 核对重点 |
|---|---|---|
| 基础显示 10 项 | `.txt` `.rtf` `.htm` `.html` `.xml` `.pdf` `.jpg` `.png` `.tif` `.bmp` | 编码、实际内容类型、图片及多页显示；办公 XML 需要按结构显示 |
| Word Open XML 4 项 | `.docx` `.dotx` `.docm` `.dotm` | 分页、图片、表格、模板；含宏文件查看静态内容 |
| 表格 12 项 | `.xls` `.xlsx` `.csv` `.xlt` `.xltx` `.xlsm` `.xltm` `.et` `.ett` `.dbf` `.prn` `.dif` | 工作表、数据类型、已有公式结果、数字格式、配套文件 |
| 旧文字和网页归档 6 项 | `.doc` `.dot` `.wps` `.wpt` `.mht` `.mhtml` | 版本识别、正文、图片、表格、归档中的资源 |
| 演示 11 项 | `.ppt` `.pptx` `.pptm` `.pot` `.potx` `.potm` `.pps` `.ppsx` `.ppsm` `.dps` `.dpt` | 每页文字、图片、基本图形、页面尺寸；动画另行记录 |
| 特殊定义 3 项 | `.xla` `.xlam` `.ts` | 按阶段 0 得到的格式定义和样本实施 |

以上合计为公开清单里的 46 个后缀。第 47 项已按用户选择补入 ODT，采用办公兼容组件。官网宣传数与清单差额继续作为来源记录。

交付物：逐格式支持报告、对应样本的显示证据、更新后的格式目标数据。

验收：每种可显示文档至少核对普通内容和复杂内容样本；模板及含宏变体分别验证。表格核对单元格值和类型，文字与幻灯片核对完整页面，图片核对尺寸和页数。定义不明、样本缺失、局部内容丢失均单独记录。

扫描 PDF 正常显示计入 PDF 阅读；对扫描图像识别文字属于另一个可选能力，不混入文字型 PDF 搜索验收。复杂动画、嵌入对象和公式重算也分别计入能力范围。

## 八 阶段 5 加入基础编辑

先实现纯文本和 CSV 的修改与另存为，再评估 Word 少量文字修改、表格普通单元格修改及 PDF 高亮和批注。每种编辑能力单独验证后启用，阅读功能持续保留。

工作内容：

1. 明确每种格式提供哪些编辑操作，以及保存原格式还是导出另一种格式。
2. 默认另存为；覆盖前处理目标已经存在和原文件被外部修改的情况。
3. 纯文本核对编码和换行，表格核对数字、公式、其他工作表及格式，Word 核对图片、表格和分页。
4. 保存后的文件重新打开，与修改前的内容核对；同时使用独立查看器检查可读性。
5. 给出未保存修改提示，支持取消关闭；保存中断时保留原文件和可恢复的编辑状态。

交付物：编辑操作清单、另存为功能、保存后的文件样本及内容对比结果。

验收：只出现预期修改，其他内容完整。预览库输出的网页和提取出的单元格数据不能直接作为原格式保真保存的证明。

## 九 阶段 6 轻量化和发布

下面是初始工程预算，属于开发目标。阶段 1 得到真实数据后复核；调整时记录原因和对使用体验的影响。

| 项目 | 初始目标 | 统计范围 |
|---|---|---|
| 主程序发布包 | 压缩包不超过 30 MiB | 包含必需程序和静态资源；公共运行时与可选组件另列实际增量 |
| 空窗口启动 | 本地 SSD 条件下中位数不超过 3 秒 | 从启动到窗口可以操作，必需运行时已安装 |
| 空闲内存 | 主程序及其全部子进程合计不超过 200 MiB | 单窗口、未打开文件、无其他兼容任务 |
| 空闲兼容引擎 | 文件处理结束并关闭后 30 秒内回收 | 后台引擎及其子进程 |
| 全部组件安装 | 如实公布实测总占用 | 主程序、组件、缺失运行时增量及缓存分别列出 |

MiB 是按 1024 计算的文件大小单位。性能测试记录机器、磁盘和组件版本；启动至少记录 5 次冷启动和 10 次重复启动的原始结果、中位数和最慢值。冷启动指软件与对应引擎尚未运行，不等同于每次重启电脑。

工作内容：优化组件延迟加载、预览复用、大文件读取和缓存清理；验证长期阅读和反复开关文件；制作发布包和双击启动入口；在缺少运行时的环境中验证安装，在离线环境中验证已安装组件的查看。

缓存依据文件内容、组件版本和影响显示的选项判断是否可复用。原文件变化或组件更新后，旧预览不能继续作为最新内容显示。组件回收不会删除用户原文件。

交付物：本地可运行发布包、依赖清单、格式覆盖报告、体积和内存测量报告、安装及卸载验证结果。

验收：安装、打开、阅读、另存为、组件更新及缓存清理完成相应测试。只有已经取得本软件显示证据的格式写入发布支持清单；识别数量、实现数量和验证数量分别统计。

## 十 工作记录与推进条件

| 阶段 | 当前状态 | 进入下一阶段的条件 |
|---|---|---|
| 0 格式和样本 | 核心合成样本齐全；原生 WPS 与特殊定义待补 | 各项有明确查看对象与核对样本 |
| 1 引擎验证 | PDF / DOCX / 表格与旧 Office 已跑通；原生 WPS 待验 | 扩充版本、复杂排版与资源测量 |
| 2 阅读软件 | 阅读与关键流程已实现并做程序内部验证 | 实际窗口鼠标、拖拽及打印验收 |
| 3 按需安装 | 下载、校验、提取和取消恢复已验证 | 补版本回退与缺少运行时的环境 |
| 4 格式覆盖 | 持续推进，逐项状态见格式清单 | 各项按真实样本更新状态；来源缺口单独解决 |
| 5 基础编辑 | TXT / CSV 编辑与另存为通过 | Word / Excel / PDF 编辑单独评估 |
| 6 发布 | 本机可运行包已生成并测量 | 新机器、长期压力和完整卸载检查 |

各阶段按模块推进。基础显示模块、样本准备和文档整理可以在不依赖未解决格式的情况下继续；更换关键引擎、采用收费授权或调整明确的产品目标时，先提交实际对比结果。

开发产生的临时文件统一放在项目 `tmp` 文件夹；完成后清理本次生成的临时内容。源码、可复现样本和交付报告按各自目录保存。应用日常运行的用户缓存由软件管理，独立于开发临时目录。

具体工期以阶段 1 的结果编排；格式兼容、编辑保存和组件授权是主要变量。当前安排以可验证的交付顺序为准。
