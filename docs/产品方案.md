# 产品方案

确认日期：2026-10-12

## 产品定位

制作 Windows 本地文档查看器。收到文件后可以双击打开，也可以拖进软件，主要用来阅读文字文档、表格、幻灯片、PDF 和清单中的图片。基础编辑服务于少量修改，查看质量和轻量化排在前面。

最终格式范围按 WPS 的 47 种宣传目标推进。公开清单中的 46 个后缀已经逐项登记，第 47 项待来源确认。[WPS 宣传页](https://www.wps.com/feature/file-opener/)和[技术规格页](https://www.wps.com/tech-specs/)是清单依据。

## 已确认的安装方式

用户选择“主程序保持小巧，遇到需要的格式时再安装对应组件”。

主程序、文字预览、表格读取和办公兼容组件分别管理。首次需要尚未安装的组件时，在软件内展示它的名称、下载量和安装后的占用，提供安装操作。组件安装完成后重复打开文件可以离线使用。

安装同一个兼容组件可以覆盖多个相关格式。不能给每个后缀复制一套大型引擎，也不能在启动时把全部引擎一起加载。组件是否真正能拆分、各组件实际有多大，要在技术验证中测量。

## 阅读功能

- 双击文件、打开文件、拖入文件。
- 缩放、搜索、复制文字；支持多文件切换。
- 文字文档保留段落、图片、表格、页眉页脚和分页。
- 表格切换工作表，显示单元格的值、格式和合并区域；日期、长编号和前导零不得读错。
- 幻灯片逐页查看，保留文字、图片及基本图形；播放动画与静态查看分别计入功能。
- PDF 支持翻页、缩放、搜索可提取的文字；扫描件也必须正常显示。
- TIFF 包含多页时能切换页码。

复杂排版、嵌入对象、图表和缺失字体是单独的验证项。不能以“文件打开了”代替内容正确、排版正确。

## 基础编辑

基础编辑的具体操作范围尚未由用户逐项确认。技术验证先考虑以下候选能力：

| 类别 | 候选操作 | 需要验证的保存行为 |
|---|---|---|
| 纯文本 | 修改文字、查找替换 | 保留编码及换行方式 |
| 文字文档 | 修改少量文字、简单字样 | 保留图片、表格、分页及其他原有内容 |
| 表格 | 修改普通单元格 | 保留数字类型、公式、格式和其他工作表 |
| PDF | 添加批注、高亮 | 再次打开后批注位置和内容正确 |
| 幻灯片、图片 | 首先完成查看 | 需要时另行定义编辑操作 |

默认查看，编辑需要主动进入。第一次编辑保存优先采用另存为，避免在保存能力未验证时覆盖原文件。原格式保存和导出为其他格式分别显示。

带宏文件（含自动执行代码的文件）以查看静态内容为目标。读取单元格中保存的计算结果、重新计算公式、执行宏是不同能力；软件不通过运行文档中的代码获得“查看通过”。

## 主程序技术选择与组件候选

建议主程序采用 C# + .NET 10 LTS + WPF（Windows 桌面界面框架），配合 WebView2 显示文档；预览页面采用 TypeScript + HTML/CSS。主程序管理窗口、文件、组件和缓存，格式组件负责读取与显示。详细分工见 [技术栈](技术栈.md)。

优先复用系统已有组件。[微软说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)确认 Evergreen WebView2 可由多款软件共享；分发仍需要检测机器是否已经安装。

本机原有 Windows 桌面运行时和 WebView2 Runtime；开发过程中已在项目内准备 .NET SDK 10.0.401。当前实测与剩余工作见 [开发进度](开发进度.md)。.NET 8 将在 2026-11-10 结束支持，.NET 10 LTS 支持到 2028-11-14，选择依据见 [微软支持政策](https://dotnet.microsoft.com/en-us/platform/support/policy)。面向其他电脑的发布包，仍须分别计入缺失依赖的安装成本。

| 模块 | 候选实现 | 核实到的依据 | 需要实测的部分 |
|---|---|---|---|
| PDF、文本、图片 | 系统能力、WebView2 或原生控件 | 微软文档支持 WebView2 导航到本地 PDF | 中文搜索、大文件、多页图片、实际内存 |
| Word Open XML | docx-preview | 作者仓库提供 DOCX 转网页预览 | 复杂排版、模板和含宏变体，不能把网页近似显示当作完全还原 |
| 表格 | SheetJS | 官方格式表包含 XLSX、XLS、CSV、DIF、PRN、DBF 和 ET 等 | 图表、条件格式、公式缓存、样本版本、编辑保真 |
| 旧版 Office、WPS 格式及幻灯片 | 可选办公兼容引擎，以 LibreOffice 为验证候选 | 官方过滤器表列出多种 Word、Excel、PowerPoint 格式及 WPS 后缀 | 实际内容识别、版本兼容、转换质量、组件体积和启动代价 |

依据：

- [WebView2 本地内容](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/working-with-local-content)
- [docx-preview 作者仓库](https://github.com/VolodymyrBaydalka/docxjs)
- [SheetJS 格式列表](https://docs.sheetjs.com/docs/miscellany/formats/)
- [SheetJS 本地脚本分发](https://docs.sheetjs.com/docs/getting-started/installation/standalone/)
- [LibreOffice 格式过滤器](https://help.libreoffice.org/latest/en-US/text/shared/guide/convertfilters.html)

可选引擎在独立进程中运行，完成转换后退出或经受控空闲策略回收；主界面显示结果。启动、转换、取消及崩溃必须能分别处理，不能让后台兼容引擎阻塞窗口。

这条路线可能让首次安装小巧，但安装全部兼容组件后的总占用仍可能较大。最终以“主程序 + 已安装组件 + 缺失的公共运行时 + 缓存”的实际增量记录。

## 尚待解决的格式定义

- 第 47 项：公开后缀名单只有 46 项，尚不能确认缺少哪一个。
- `.ts`：官网列在演示格式里，尚未找到明确的格式定义；不能将视频或程序源码混为演示文稿。
- `.xla`、`.xlam`：微软定义为 Excel 插件。可能没有普通工作表，必须先定义查看对象与验收方式。[微软格式说明](https://support.microsoft.com/en-us/office/file-formats-that-are-supported-in-excel-0943ff2c-6014-4e8d-aaea-b83d51d46247)
- `.xml`：内部可能是普通 XML、Word XML 或表格 XML。只显示源代码不能算办公文档已正确查看。
- WPS 系列后缀：按内容及版本分别测试；LibreOffice 官方表里的扩展名登记不能作为所有 WPS 版本兼容的证明。
- 加密文件、嵌入对象、扫描件文字识别以及缺失字体处理：列为独立能力，按实际文件补充验收样本。

## 推进顺序

分阶段任务、交付物和验收条件见 [开发计划](开发计划.md)。

1. 技术验证：制作最小 Windows 程序，测量 PDF、DOCX、XLSX 的实际打开效果、启动时间、安装体积和内存。同时验证兼容引擎能否覆盖旧版 Office 和 WPS 格式。
2. 阅读版本：打通统一打开、拖入、阅读工具和按需组件管理。把各格式的实际实现状态写回清单。
3. 扩展覆盖：补齐模板、含宏变体、旧版格式、网页归档、数据交换格式、WPS 系列和特殊项；主程序按需调用对应组件。
4. 基础编辑：按候选操作逐项实现，验证修改保存后原有内容是否完整。
5. 发布验收：逐项记录实测证据，测试缺失组件、下载中断、损坏文件和运行时缺失；制作本地可运行安装包。

分阶段决定实现顺序，最终覆盖范围仍以全部目标为准。

## 验收记录

每种格式分别记录识别、读取、显示、编辑和保存。格式目录用以下状态：

- NOT_IMPLEMENTED：尚未实现。
- IMPLEMENTED：代码已有，样本验收未完成。
- VERIFIED：在本软件中完成样本及显示核对，有证据。
- FAIL：已运行但未满足对应验收条件。
- NOT_RUN：尚未执行该项验证。
- BLOCKED_ENV：被组件、样本或运行环境阻挡。

格式状态只有与实际显示证据关联后才能计入已验证数量。后缀匹配、构建成功、库的支持声明或样本提取出文本，不单独计为显示验收通过。

轻量化记录首次安装和全部组件安装两种情况；记录冷启动、重复打开、空闲内存、文档打开后全部子进程内存、关闭后的回收和缓存大小。文件样本及测量机器配置一起记入报告，目前不预先编造体积或速度数字。
